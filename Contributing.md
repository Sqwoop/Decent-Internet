# Contributing to Decent-Internet

Thank you for your interest in contributing to Decent-Internet.

Our mission is to develop affordable, decentralized, privacy-first internet infrastructure that benefits the people who use it and help maintain it.

We welcome individuals who share our commitment to transparency, security, accessibility, and open development.

## Guiding Principles

All contributions should support the following principles:

- **Privacy by Design:** Protect user information and minimize unnecessary data collection.
- **Security First:** Prioritize secure, reliable, and independently auditable infrastructure.
- **Decentralization:** Reduce unnecessary central points of control or failure.
- **Transparency:** Maintain clear, understandable, and inspectable technical processes.
- **Efficiency:** Respect users' computing resources, bandwidth, storage, and electricity.
- **User Autonomy:** Preserve voluntary participation and meaningful control over shared resources.
- **Interoperability:** Favor open standards and technologies that avoid unnecessary vendor lock-in.

## Ways to Contribute

Contributions may include:

- Software development and bug fixes
- Network architecture and protocol design
- Security research and cryptographic review
- Resource-sharing and contribution-accounting models
- Technical documentation
- Accessibility improvements
- Testing and performance analysis
- Research proposals

## Contribution Process

1. Review the project's existing documentation and open issues.
2. Open an issue to discuss substantial changes before implementing them.
3. Fork the repository and create a dedicated development branch.
4. Make your proposed changes and document their purpose.
5. Submit a pull request explaining the changes, testing performed, and potential risks.
6. Address feedback from project maintainers.

All pull requests are subject to review. Submission does not guarantee acceptance.

## Code Review and Approval

Decent-Internet maintains a structured review process to protect the integrity of its software.

- Contributions must be reviewed before integration into protected branches.
- Contributors cannot approve their own changes.
- Security-sensitive changes should receive additional review when qualified reviewers are available.
- Changes involving encryption, routing, resource allocation, identity, or financial accounting require particular scrutiny.
- Maintainers may reject contributions that conflict with the project's principles, architecture, or security requirements.

Final authority over official repository changes remains with authorized project maintainers.

## Security Requirements

Contributors must not introduce:

- Undisclosed telemetry or user tracking
- Hidden resource consumption
- Unauthorized data collection
- Backdoors or intentionally weakened security controls
- Undocumented network communications
- Malicious dependencies or concealed executable behavior

Any collection or processing of user information must be explicitly documented and justified.

Security vulnerabilities must be reported according to the project's SECURITY.md policy, not through public issues.

## Resource-Sharing Requirements

Features involving contributed computing power, bandwidth, or storage must be designed around informed consent and user control.

Proposals should address:

- Explicit user authorization
- Configurable contribution limits
- Resource usage visibility
- Safe termination or withdrawal
- Protection against unauthorized workloads
- Verifiable measurement and accounting

## Community Conduct

Participants must communicate respectfully and constructively.

Harassment, threats, discrimination, spam, and malicious conduct are not permitted.

Technical disagreements should be addressed through evidence, documentation, and reasoned discussion.

## Licensing

Contributions accepted into the repository are intended to be distributed under the repository's Apache License 2.0 unless explicitly stated otherwise.

Contributors must have the legal right to submit their work and should identify relevant third-party code, licenses, and dependencies.

## Project Governance

Decent-Internet is an independently directed initiative developed through open collaboration.

Community participation does not automatically grant administrative privileges, company ownership, or decision-making authority.

Governance processes may evolve as the project grows.
