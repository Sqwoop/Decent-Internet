# Decent-Internet Security Policy

## Our Commitment to Security

Security and privacy are foundational principles of Decent-Internet.

We aim to develop decentralized infrastructure that protects users, preserves system integrity, and allows independent security verification.

We encourage responsible security research and coordinated vulnerability disclosure.

## Supported Versions

Decent-Internet is currently in its foundation and research phase.

No production-ready software versions have been released, and no versions are currently supported for production security updates.

This policy will be updated as software becomes available.

## Reporting a Vulnerability

Please do not publicly disclose suspected security vulnerabilities before they have been evaluated.

To report a vulnerability, use GitHub's private vulnerability reporting feature, when available, through the repository's Security section.

Include the following information when possible:

- Description of the suspected vulnerability
- Affected components or files
- Steps to reproduce the issue
- Potential security or privacy impact
- Suggested mitigations, if known

Do not post sensitive exploit details, private credentials, or personal information in public GitHub issues.

## Security Review Process

Security reports will be evaluated by authorized project maintainers.

Our intended process includes:

1. Reviewing the report and determining its scope.
2. Assessing the vulnerability's severity and potential impact.
3. Developing and reviewing a proposed fix.
4. Testing the fix before integration.
5. Coordinating disclosure and publishing appropriate security information.

Response times and remediation timelines are not yet guaranteed.

## Security-Sensitive Components

As development progresses, particular attention will be given to:

- Encryption and key management
- Network routing and node authentication
- Resource-sharing permissions
- Workload isolation and sandboxing
- Storage security and data integrity
- Identity and access control
- Contribution accounting and financial mechanisms
- Software update and dependency security

## Responsible Research

Researchers should:

- Use their own systems or systems they are explicitly authorized to test.
- Avoid accessing or modifying other people's information.
- Avoid disrupting services or network availability.
- Limit testing to what is necessary to demonstrate a vulnerability.
- Report findings privately and provide maintainers an opportunity to investigate.

This policy does not grant permission to test third-party infrastructure or systems without authorization.

## Transparency

Decent-Internet intends to support independent security review, transparent development, and verifiable software builds.

As the project matures, we aim to publish security advisories and document significant vulnerabilities and their resolutions.

---

**Security is not a feature added at the end. It is a requirement from the beginning.**
